# 文化祭ブロックチェーン 改造マニュアル

「動かす」「微調整する」ではなく、コードに手を入れて機能を追加・変更したい人向けの
レシピ集です。「ここを直すとここに影響が波及する」という設計上のポイントを
先に押さえてから、よくある改造パターンを手順化しています。

---

## 0. 改造前に知っておくべき全体構造

呼び出し関係はおおよそ以下のようになっています。上から下へ依存します
(下のレイヤーは上のレイヤーを知らない)。

```
templates/*.html         ← 画面の見た目(Jinja2)
    ↑
画面/*.py (Flask Blueprint) ← 1画面ぶんのルーティングとロジック
    ↑
状態.py                    ← アプリ全体で共有するシングルトン(Blockchain, DB等)
    ↑
ブロックチェーン/*.py       ← ブロックチェーンのコアロジック
暗号/*.py                  ← ハッシュ・署名
通信/*.py                  ← ノード間通信
データベース/*.py           ← SQLite永続化
```

**改造するときは、まず「どのレイヤーの話か」を意識してください。**
- 見た目だけ変えたい → `templates/` と `static/css/style.css` だけ触ればよい
- 画面の動き(送金条件など)を変えたい → `画面/*.py`
- ブロックチェーンの仕組み自体を変えたい → `ブロックチェーン/*.py`、影響範囲が広いので要注意(後述)

`状態.py` はアプリ起動時に一度だけ実行され、`blockchain` / `database` などの
インスタンスをモジュールレベル変数として保持しています。他のファイルは
`import 状態 as state` として `state.blockchain` のように参照します。
**新しく作ったファイルからこれらにアクセスしたい場合も、必ず `状態.py` 経由にしてください**
(直接 `Blockchain()` を新規生成すると、別のチェーンができてしまい整合性が壊れます)。

## 1. レシピ: 新しい画面(ページ)を追加する

例: `/ranking` という「残高ランキング」画面を追加する場合。

### 手順

1. **表示ロジックを書く(任意、無くてもよい)**
   `表示/ランキング表示.py` を新規作成し、集計ロジックを書く。

   ```python
   # 表示/ランキング表示.py
   def build_ranking(chain, accounts):
       balances = []
       for acc in accounts:
           from 残高計算 import BalanceCalculator
           bal = BalanceCalculator.calculate_balance(chain, acc["public_key"])
           balances.append({"username": acc["username"], "balance": bal})
       return sorted(balances, key=lambda x: x["balance"], reverse=True)
   ```

2. **画面(Blueprint)を書く**
   `画面/ランキング画面.py` を新規作成。既存の `画面/アカウント画面.py` を
   コピーして書き換えるのが早いです。

   ```python
   import sys, os
   sys.path.append(os.path.join(os.path.dirname(__file__), ".."))
   import 状態 as state

   sys.path.append(os.path.join(os.path.dirname(__file__), "..", "表示"))
   from ランキング表示 import build_ranking

   from flask import Blueprint, render_template

   ranking_bp = Blueprint("ranking", __name__)

   @ranking_bp.route("/ranking", methods=["GET"])
   def ranking_page():
       accounts = state.account_repo.load_all_accounts()
       ranking = build_ranking(state.blockchain.chain, accounts)
       return render_template("ranking.html", ranking=ranking)
   ```

3. **`app.py` にBlueprintを登録する**

   ```python
   from ランキング画面 import ranking_bp   # 他のimportの近くに追加
   app.register_blueprint(ranking_bp)      # register_blueprintの並びに追加
   ```

4. **テンプレートを追加する**
   `templates/ranking.html` を新規作成(既存の `account.html` をコピペして
   テーブル部分だけ書き換えるのが早い)。

   ```html
   {% extends "base.html" %}
   {% block title %}ランキング{% endblock %}
   {% block content %}
   <div class="page-head"><h1>残高ランキング</h1></div>
   <div class="panel">
     <table>
       <thead><tr><th>順位</th><th>ユーザー名</th><th>残高</th></tr></thead>
       <tbody>
       {% for r in ranking %}
         <tr><td>{{ loop.index }}</td><td>{{ r.username }}</td><td>{{ r.balance }}</td></tr>
       {% endfor %}
       </tbody>
     </table>
   </div>
   {% endblock %}
   ```

5. **ナビに追加する(任意)**
   `templates/base.html` の `<nav class="nav">` 内に1行追加。

   ```html
   <a href="{{ url_for('ranking.ranking_page') }}">ランキング</a>
   ```

6. 動作確認: `python -m py_compile 画面/ランキング画面.py` で構文エラーが無いか確認してから
   `python app.py` で起動し、`/ranking` にアクセスする。

## 2. レシピ: ブロックに新しい項目(フィールド)を追加する

例: ブロックに「採掘にかかった時間(秒)」を記録したい場合。

**⚠️ 注意: この改造は影響範囲が広いです。** ハッシュ計算の対象が変わるため、
**既存のチェーン(SQLiteに保存済みのデータ)とは互換性が無くなります。**
改造後は `ノードデータ/*.db` を削除してジェネシスブロックからやり直してください。

影響するファイル一覧:

| ファイル | 変更内容 |
|---|---|
| `ブロックチェーン/ブロック.py` | `_KEYS` タプルと `__init__` に新フィールドを追加 |
| `暗号/ハッシュ.py` | `calculate()` で連結する項目に新フィールドを追加(**ここを変えると過去のハッシュ値と一致しなくなる**) |
| `ブロックチェーン/採掘.py` | `mine()` 内でブロック生成時に新フィールドの値をセット |
| `データベース/ブロック保存.py` | `save_block` / `save_chain` / `load_chain` のSQL文とdictに新カラムを追加 |
| `表示/チェーン表示.py` | 表示したい場合はここに整形ロジックを追加 |
| `templates/index.html` 等 | 表示したい場合はここにHTMLを追加 |

**鉄則: `暗号/ハッシュ.py` の `calculate()` が連結する項目を変えたら、
新しいチェーンを作り直す(DBを消す)まで既存データとの整合性は取れません。**
これは仕様というより、ハッシュチェーンの性質そのものです(改造の失敗ではありません)。

## 3. レシピ: コインの呼び方・単位を変える(例:「コイン」→「文化祭ポイント」)

表示上の文言なので、影響はテンプレートだけです。

対象ファイル(文字列 `コイン` で全文検索して置換):

```bash
grep -rn "コイン" templates/
```

該当箇所をまとめて `文化祭ポイント` などに置換すればOKです。
ロジック側(`ブロックチェーン/採掘.py` の `MINING_REWARD` など)は数値だけなので
変更不要です。

## 4. レシピ: 採掘演出を派手にする(効果音・アニメーション)

`static/js/main.js` の採掘フォーム送信時の処理に手を加えます。

```javascript
// static/js/main.js の mineForm.addEventListener("submit", ...) の中に追記
const audio = new Audio("/static/sound/mining.mp3");  // 事前に static/sound/ へ音声ファイルを配置
audio.play().catch(() => {});
```

音声ファイルを置く場合は `static/sound/` フォルダを新規作成して配置してください
(`static/` 以下は `url_for('static', filename='...')` でそのまま配信されます)。

採掘中のプログレス演出(疑似アニメーション)を足したい場合は、`mine.html` に
`<div id="mining-progress"></div>` を追加し、`main.js` 側でボタン押下後に
CSSアニメーションのクラスを付与する、といった実装になります。

## 5. レシピ: デザイン(配色・フォント)を変える

`static/css/style.css` 冒頭の `:root { ... }` にあるCSS変数だけを書き換えれば、
サイト全体の配色が一括で変わります。

```css
:root {
  --bg: #0f1420;      /* 背景色 */
  --amber: #e8a33d;   /* メインアクセント色(ボタン・強調) */
  --teal: #3ddac0;    /* 成功・正当を示す色 */
  --red: #e5484d;     /* 警告・改ざん検知を示す色 */
}
```

学校のテーマカラーに合わせたい場合はここだけ変更すれば十分です。
個別のパーツの微調整をしたい場合は、同じファイル内の該当クラス
(`.block-card`, `.btn`, `.stat-card` など)を探して直接編集してください。

## 6. レシピ: 採掘の難易度を来場者の混み具合に応じて動的に変える

`状態.py` の `miner = Miner(difficulty=4)` を書き換えるだけなら固定値ですが、
「並んでいる人数が多い時間帯だけ難易度を下げる」ような動的制御をしたい場合は、
`画面/採掘画面.py` の `mine_run()` 内で `state.miner.difficulty = ...` を
リクエストのたびに書き換えることも可能です。

```python
# 画面/採掘画面.py の mine_run() 冒頭あたりに追加する例
import time
# 直近の採掘リクエスト数を数えて混雑度を判定するなど、簡易なロジックを書き足せる
```

凝ったことをしたい場合は `状態.py` に「直近の採掘リクエスト時刻リスト」を
持たせて混雑度を判定する、といった実装が考えられます(標準では未実装)。

## 7. 改造時の安全な進め方(共通の心得)

1. **改造前にZIPごとバックアップを取る**、または `git init` してコミットしておく。
   ```bash
   cd 文化祭ブロックチェーン
   git init
   git add -A
   git commit -m "改造前のバックアップ"
   ```
2. **改造したファイルは必ず構文チェックしてから起動する。**
   ```bash
   python -m py_compile 画面/ランキング画面.py
   ```
3. **DBのスキーマやハッシュ計算対象を変えたら、`ノードデータ/*.db` を削除してから起動する。**
   (削除しないと、新しいコードが古い形式のデータを読んで壊れたように見えることがあります)
4. **本番(Ubuntu)に配る前に、必ず一度その環境で `python app.py` が起動することを確認する。**
5. うまく動かないときは、まず `python -m py_compile <変更したファイル>` で
   構文エラーが無いか確認し、次にターミナルに出るエラーメッセージの
   最後の数行(トレースバック)を読む。「どのファイルの何行目で」「何のエラーか」が
   ほぼ必ず書かれています。

## 8. どうしても分からないときのために

- `仕様書.md` — 各ファイルが何を担当しているかの全体像
- `操作説明書.md` — 動かし方・環境変数・トラブルシューティング(運用寄り)
- 本ファイル(`改造マニュアル.md`) — コードを直接変更する人向け(開発寄り)

各Pythonファイルの冒頭には、そのファイルの役割と設計意図をコメントで
書いてあります。改造前に一度目を通すと、影響範囲の見積もりがしやすくなります。
